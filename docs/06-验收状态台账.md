## 1. 目标与验收口径

- 目标：把 Clash Mini 3.2.2 按 1:1 语义做**语言移植**为 C++20 + Win32 + Direct2D 客户端，唯一公开差异是显示名 `Clash Win`（`01-目的与方针.md:5-7`）。
- 总体验收：双开 Mini 与 Clash Win 执行同一脚本化操作序列，两实例的 UI 截图、生成的配置文件、注册表/服务状态全部等价（`phase1/03_PRD.md:10-19`）。
- 第一性是源码对照；截图 / OCR / 像素统计只作验证手段，不得反推 UI（`02-方法与流程.md:22-29`）。
- 独立可用性 P0：`检测 → 提权安装（UAC）→ 启动服务 → 等待 IPC 就绪 → 以 SYSTEM 身份起内核`，每步失败要有可见提示与回退；任何「TUN 可用」结论必须附完整链路证据（`sc query` RUNNING、内核 Session#=0、境外三条 URL 通），**仅在 Mini 已装服务的机器上通过，不得宣布可用**（`01-目的与方针.md:27-35`）。
- 方针不变：不新增页面、不改内核、不做兼容层；**2026-11-07 起对外发布已获用户当场全权授权**，发布动作自主执行、不再逐动作确认（总纲 `移植基本准则.md` §5.4 第二条）。旧「不对外发布 / 不建 Release / 不推 tag / 不上传资产」口径已被覆盖，原引用的 `01-目的与方针.md:47-56`、`README.md:22-24`、`docs/README.md` 相应行已同步修订；签名状态只记录、不作发布门禁（§4 第 6 条）。

8. **命名管道口径矛盾 —— 已定性为文档口径问题，非代码缺陷**（详见 `evidence/2026-11-06-root-cause.md` §1）：`01-目的与方针.md:21` 要求 `\\.\pipe\clash-win-mihomo` 自有名字并称「凡 Mini 侧出现 `mini-mihomo-win` 字样的硬编码都必须同步改」，`docs/README.md:24` 记实际走 `\\.\pipe\mini-mihomo-win`。核实：`src/util/dirs.cpp:207-211` 的 `ipc_path()` 是全仓唯一运行时定义，值经 `-ext-ctl-pipe` 参数（`src/core/core_manager.cpp:165`）与配置 `external-controller-pipe`（`src/config/clash.cpp:208`）注入，**不是内核硬编码**；Mini 侧用 `\\.\pipe\mini-mihomo`（`03-踩坑与避坑清单.md:57`），`mini-mihomo-win` 正是本项目为共存自造、已错开的名字。方针把本项目自己的值误当成 Mini 硬编码，前提写错；「自有名字、不连到对方内核」实质已达成。服务 IPC `\\.\pipe\clash-verge-service` 是**刻意共用**（方针 `:25`），靠 `X-IPC-Magic` 与「谁开谁写」约定隔离。**本轮未改任何代码**；若要统一应改方针措辞，而非动源码。

9. **工具环境限制（非项目缺陷）**：`sc.exe` 被执行环境程序黑名单禁用，服务状态无法采集，P0 脚本如实记 `SERVICE-QUERY-UNAVAILABLE / UNKNOWN`；`Add-Type` / COM 亦被拦，无法用 Windows 回收站 API。`Start-Process -Verb RunAs` 在无交互桌面的工具会话中会被取消，故完整 UAC 验收改由后台任务完成（首次因工具超时中断，见 `evidence/2026-11-06-uac-partial-run.md`）。未重试、未绕行被禁程序。

| 脚本 | 覆盖 | 说明 |
| --- | --- | --- |
| `scripts\acceptance_uac.ps1` | C 节原 #1～#4；#0/#5 标 `MANUAL` | 一次管理员授权、逐项自动留证并产出报告；执行顺序 **#2 打包 → #1 验签 → #3 `/KEEP` → #4 卸载**（`build_installer.ps1` 会删建 `$OutFile` 且内部已签名，故 #1 只验证、无效才补签）；`-DryRun` 只预演不改动系统；#2 会覆盖 `dist\`、`installer\stage\` 并重签 `dist\*setup.exe`，可用 `-SkipRebuild` 沿用现有包；#3/#4 会重装/卸载程序，可用 `-SkipDestructive` 跳过；提权失败固定 `exit 2`，不写报告 |

## 6. 纪律

- **发布口径（2026-11-07 更新）**：用户已全权授权对外发布，push / 建 Release / 推 tag / 上传资产自主执行，不再逐动作确认（总纲 `移植基本准则.md` §5.4 第二条）。旧「未取得针对该动作的确认前不 push / 不建 Release / 不推 tag / 不上传资产」已作废，保留作时间线。
- `sidecar/` 5 个上游二进制：不清理、不替换、不升级、不重新编译，只做完整性校验。
- `ClashVerge` 参考目录：只读参考，不得改动、移动或覆写。
- 任何「TUN 可用 / P0 通过」的结论，必须附「服务从缺失到就位」完整链路证据；仅在 Mini 已装服务的机器上通过，不得宣布可用。
