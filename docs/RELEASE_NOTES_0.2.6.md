# Clash Win v0.2.6 发布说明

本版本聚焦两类用户可见问题的修复，并对发版流程做了根治性加固。

## 用户可见修复

### 1. UAC 提权前先自报家门
此前启用 TUN 模式 / 安装系统代理服务时，Clash Win 会触发 UAC 提权弹窗，但被提权的
`clash-verge-service-install.exe` 是未签名二进制，Windows 只能显示「未知发布者」，
用户无法判断这个请求到底来自谁（与 Clash Mini 表现不一致）。

v0.2.6 在真正弹 UAC **之前**，先弹出来源明确的确认框：
「Clash Win 需要管理员权限，用于安装/管理系统代理服务（TUN 模式 / 联网所需）」，
点确定才继续。即使安装包本身未签名，用户也能 unambiguous 地知道这是 Clash Win 发起的请求。

### 2. 内核缺失自动恢复（节点表不再空白）
v0.2.5 的部分安装（干净安装 / 归档漏内核的场景）会出现代理节点表空白——
根因是 `win-mihomo.exe` 内核二进制没有随安装包送达，而旧逻辑只在用户手动点「内核更新」时才去下载。

v0.2.6 启动时若检测不到内核，会**自动从 GitHub（MetaCubeX/mihomo）下载并校验** `win-mihomo`
到 `cores/` 目录后重试启动，等价于 Clash Mini「内核始终存在」的保证。常态下安装包已含内核，
此恢复路径是兜底，仅在离线 / 归档异常时触发。

### 3. sidecar 内核路径修正
`dirs.cpp` 的 `sidecar_core_path()` 原先错误指向 exe 根目录而非 `<exe>\sidecar\`，
已修正。配合上述自动恢复，内核定位更稳健。

## 工程与发版流程加固

- **根治「发布漏内核」**：新增三道锁——`build_installer.ps1` 硬性要求内核存在、
  `release.yml` 在归档缺失时从上游补齐并按基线校验 SHA256、`release.yml` 断言 setup 体积 > 35MB；
  预检脚本新增 **GATE 6** 校验本地 sidecar 含内核。v0.2.5 的 `setup.exe` 曾因外部归档漏内核、
  且流程无任何拦截，打出不含内核的安装包。
- **构建环境治理**：新增 `scripts/build.ps1` 标准编译入口，构建前剥离 WorkBuddy 透明代理注入的
  大小写重复 `*_PROXY` 变量，根治 MSBuild「字典关键字冲突」编译崩溃。

## 升级说明
- 自动更新：需在支持 minisign 验签的前提下可用（见已知限制）。
- 手动升级：卸载旧版或直接覆盖安装均可；升级后首次启动若检测到内核缺失会自动恢复。
