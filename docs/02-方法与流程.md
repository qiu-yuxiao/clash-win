# 02 方法与流程

## 移植顺序

固定四步，顺序不可颠倒：

1. **读源码**：先读 Mini 的 TS/TSX（页面与组件）与 Rust（配置/服务/内核管控），确认每一处行为的真实实现，包括条件分支与窄窗降级（例如 `active-node-card.tsx` 的 ≤580/≤480/≤400 三档隐藏规则）。
2. **结构**：先用 `Stack/Column/Row/ScrollList` 复刻 DOM 层级与容器语义（谁覆盖谁、谁滚动、谁 flex）。结构错了，后面调样式全是徒劳。
3. **控件**：为每个叶子节点选既有 Widget（`Label/Button/IconW/Segmented/SwitchW`），不新造控件。
4. **样式与交互**：字号/间距/颜色/圆角逐项抄，交互路径（点击命中、hover、开关回调）逐条接。

## 出处门禁

UI 层每个数值/颜色字面量必须带来源标注，否则视为违规：

- `src: <Mini 文件:行号>`（规范写法）
- `←`（历史移植标记，后接出处）
- `// 豁免: <理由>`（确实无源码依据时显式豁免）

运行 `scripts/ui_src_gate.ps1` 检查，有违规会打印清单并 `exit 1`。豁免要写清"为什么没有出处"，不能拿豁免当挡箭牌——历史上正是"按截图反推"欠下的 10 处无出处常量导致了后续返工。

## 验收

**第一性是源码对照**，截图/OCR/像素统计/同屏并排只作验证手段，不能反过来用截图推断 UI。这一条必须写死：凡是"看着像"就改的，几乎都会错。

- 并排对照：两窗同屏 `cmp_<页面>.png`，逐组给结构/间距/字号/颜色结论。
- 文字类：OCR 取行高，与源码 `font-size` 换算比对（150% 缩放下 physical 行高约为 DIP×1.5）。
- 几何类：读真实窗口矩形（DPI-aware），不与"逻辑猜测"混算。
- 点击类：鼠标注入，每条留三段证据——**注入坐标 → 命中日志 → 状态变化**。缺任一段不算验证过。

## 流程纪律

- **首尾都是环境守卫，前后一律清空**：任何「启动程序做实测」的动作，前一步 `scripts\env_guard.ps1 -Phase Pre`，最后一步 `-Phase Post`；两者都**清掉全部自家进程**（`clashwin.exe`、`clashwin_test.exe` 全部实例 + 仓库 `build*`/`%TEMP%\cw*` 下的 `mini-mihomo.exe`），不设任何豁免（Clash Win 的实例都是测试启动的，不存在"用户在用的实例"）。断言：自家存活进程数 = 0、`33337/10811–10814/9108` 空闲，输出 `READY/clean` 或 `NOT READY/NOT CLEAN`。唯一排除 `clash-mini.exe` 与 `clash_verge_service`。报告必须贴 Pre 清理清单与 Post 结论。
- **网络只读，测试不碰系统设置**：Clash Win 是「使用网络」的程序，不是「设置网络」的程序。验证出网一律用显式代理（`curl -x 127.0.0.1:10811`、`Invoke-WebRequest -Proxy`）或内核 `/proxies` `/connections` 直查，**禁止为了验证去开系统代理或开 TUN**。`env_guard.ps1 -Phase Pre` 已把网卡/默认路由/IE 与 WinHTTP 代理/DNS 写入 `%TEMP%\cwrun\net_state_pre.json`，`-Phase Post` 自动比对并还原，输出 `NET-RESTORED` 或 `NET-DIRTY + 差异清单`；`NET-DIRTY` 一律算 Post 失败（退出非 0）。确需验证 TUN/系统代理时，必须显式 `-AllowNetworkChange`，并在同一命令内完成「开→验→关→还原」，报告贴还原证据。
- **小步**：一次只改一个可验证的点，改完立刻重编译。
- **每步全量测试**：`scripts/run_tests_v4.ps1`（隔离模式，见 04 篇）。不允许"先攒着一起跑"。
- **不跳步**：构建失败先解决构建，不带着编译错误改下一处；崩溃未定位不动 UI。
- **留证**：测试结果写进回复（cases/failed 数字），点击验证写坐标与日志。
- **中断可恢复**：每段结束落盘代码与结论；上下文被压缩时靠文档而非记忆恢复。

## 网络改动测试纪律（2026-11-05 断网事故后新增）

- **先回滚、再测试**：任何会改网络的功能（系统代理 / TUN / DNS / 路由 / WinHTTP）开跑前，必须先把一键回滚脚本写好，并**空跑验证过还原路径**（脚本只依赖本地文件与注册表，不依赖 DNS/外网）。测试命令必须带**超时自动还原**：90 秒内未达到预期就无条件还原；还原动作放在 `finally`/超时分支，不依赖"测试成功"分支。
- **断网 = 自断手脚**：我们与用户同机，任何可能切断本机出网的测试，优先级低于其它所有工作；回滚脚本必须本地就绪、命令不依赖网络解析；跑之前先记录基线（`ProxyEnable/ProxyServer/ProxyOverride/AutoConfigURL/AutoDetect`、DNS、默认路由），跑完按基线逐项比对。
- **停内核的顺序**：先关系统代理（或还原基线）→ 再停 TUN/删路由 → 最后杀进程。反过来的代价是整机断网（见 03 篇第 26 条）。

## 停用 Clash Mini 期间的清场与恢复约定（2026-11-05）

- **清场范围**：`scripts\env_guard.ps1` 已把 `clash-mini.exe` 与 Mini 侧 `mini-mihomo.exe`（`C:\Program Files\Clash Mini` 下）列入可清理；每条审计输出 `PID | 名称 | 路径 | 启动时间 | 结果`。
- **服务不是保留项**：`clash_verge_service` 允许 stop / delete / 由我方 `sidecar\clash-verge-service-install.exe` 安装，也允许用 Mini 安装器恢复；两个程序都应具备「缺服务就装」的能力。批次收尾的唯一硬约束是「任一方都能自行恢复」：要么服务在且 `ImagePath` 指向某一边，要么服务不存在但两边的安装器都在原位可执行——收尾时必须明确写出当前是哪种。
- **断网红线（脚本内置）**：清进程后若存在 `0.0.0.0/0 -> 198.18.x` 默认路由，自动删除；若 Wintun/Mihomo 适配器仍 `Up`，自动 `Disable-NetAdapter`；默认路由必须回到 `192.168.1.1`，否则判「断网红线」失败并打印提权命令。残留但不 Up 的 `本地连接`/`本地连接 2`（Wintun）不影响出网，按需删除。
- **下次要用 Mini 时怎么恢复**：① 直接打开 Clash Mini 应用——若服务不存在，Mini 的安装器会自行安装（这是它已有的能力）；② 若 TUN 不可用，让 Mini 重建 TUN 适配器（应用内关闭再开启 TUN，或重装 Mini）；③ 开启前确认默认路由回 `192.168.1.1`；④ 需要系统代理时再由 Mini 自己打开，不要让本程序与 Mini 同时接管。
