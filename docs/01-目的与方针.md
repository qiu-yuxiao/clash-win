# 01 目的与方针

## 目的

把 Clash Mini 3.2.2 的源码做**语言移植**，不是重做产品：前端 React/TS/Tauri 的页面结构、样式数值、交互路径，逐条翻译为 C++20 + Win32 + Direct2D 的自绘 Widget 树；后端沿用 Mini 的 Rust 语义（配置迁移、服务、内核管控、WS 抓取）。

唯一允许的公开差异是显示名 `Clash Win`（注意中间有空格），其余行为 1:1。判断"是否 1:1"的唯一依据是 Mini 源码，不是截图观感。

## 共存契约

同一台机器必须能同时运行 Mini 与本程序，因此所有"独占资源"都要错开。已在 `include/clashwin/config/constants.h:20-35` 固化：

| 资源 | Clash Mini | Clash Win |
| --- | --- | --- |
| mixed / socks / http | 10801 / 10802 / 10803 | 10811 / 10812 / 10813 |
| http guard 兜底 | 7899 | 10814 |
| external-controller | 9098（冲突向上寻位） | 9108（冲突向上寻位） |
| 单实例 / PAC | 33335（dev 33336） | 33337 |
| 控制器 secret | adapted-by-qiu-yuxiao | adapted-by-clash-win |

命名管道同理：本程序用 `\\.\pipe\clash-win-mihomo` 级别的自有名字，凡 Mini 侧出现 `mini-mihomo-win` 字样的硬编码都必须同步改（漏改会连到对方内核，症状是"配置生效但界面数据对不上"）。

**共存前提**：两程序不得同时启用 TUN 或系统代理。TUN 会抢占默认路由（`0.0.0.0/0 → 198.18.0.2`），系统代理会互相覆盖注册表。共用能力按"谁开谁写、另一侧只读"处理。

**服务名只有一个**：`clash_verge_service`。这不是"禁止安装"，而是"两程序共用同一服务、不重复抢装"。安装器检测到已存在即复用，卸载时不得粗暴删服务。

## 独立可用性（P0）

> **此前遗漏，2026-11-05 补记。**

Clash Win 必须能在**从未安装过 Clash Mini 的干净机**上全功能运行（含 TUN、系统代理）。服务自举是 Mini 的既有行为（`clash_mini_agreements.md` §1.8，附其源码 `file:line`），本程序必须 1:1 照搬，属于移植完整性，不是用户新增需求。

- 完整链路：`检测（未安装 / STOPPED / 未就绪）→ 提权安装（UAC）→ 启动服务 → 等待 IPC 就绪 → 以 SYSTEM 身份起内核`；每步失败都要有可见提示与回退。
- 禁止：假设服务存在、只发 IPC 就宣称可用、服务缺失时假装成功或跳过安装。
- 验收口径：任何"TUN 可用"的结论都必须附"服务从缺失到就位"的完整链路证据（`sc query` RUNNING、内核 Session#=0、境外三条 URL 通）；仅在 Mini 已装服务的机器上通过，不得宣布可用。

## 版本

从 `0.1.0` 起（`constants.h:18`）。历史文档里出现过的 `v3.0.10` 是错误定义，已废弃。

## 三条方针

1. **源码为唯一事实源**。任何数值、颜色、间距、文案，先落到 Mini 的"文件:行号"，再写 C++。写不出来源 = 没做完。
2. **未在 agreement 规定的一律照抄 Mini 现状**。不揣测"更好的设计"，不借机重构；Mini 有 bug 也先照抄，再由用户裁决是否偏离。
3. **1:1 能推出结论的自己定**。不把可由源码推出的事列进"待决定"清单；只有涉及品牌、共存资源、破坏性操作（卸载/替换服务）才升级给用户。

## 边界

- 不新增页面：页面集合以 Mini 为准；Mini 没有的页面不补，Mini 有的页面不许缺。
- 不改内核：Mihomo 二进制与命令行参数按 Mini 现状。
- 不做"兼容层"：不为了将来可能的需求预留抽象。
